# Design

## Context

See [proposal — Why](proposal.md#why). This is a source-based review at `3b3fa9f` (`origin/main`, refreshed 2026-10-11), using the architecture-clarity-review criteria. The sampled scenario is a targeted `catalog refresh`, including its default preview and apply branch through the shared CLI/Studio workflow; add/check appear only where they share the same implementation. This is not a project-wide architecture assessment. Source and tests were read; no live research, model calls, catalog mutation, reader timing experiment, or application test execution was performed during planning.

The [documentation index](../../../../docs/index.md), [structure](../../../../docs/project-structure.md), and [ingestion guide](../../../../docs/ingestion-process.md) identify implemented local ingestion. The broad ingestion-is-deferred wording in `openspec/config.yaml` conflicts with that documented and coded local workflow; public deployment remains outside this pilot. This proposal does not amend that background wording. The implementation and current [source workflow](../../../specs/catalog/source-workflow/spec.md), [records](../../../specs/catalog/records/spec.md), and [publication](../../../specs/catalog/publication/spec.md) are the behavior baseline. Active launch/readiness changes are not treated as implemented behavior.

### Changes since the original review

The baseline advanced from `6b3978d` to `3b3fa9f`. Selective logging/observability (#15) and shared Studio execution (#16) materially changed orchestration; discovery filter changes (#17) and worktree setup do not affect the proposed extractions. The three transformation owners are still embedded in agent, so the bounded pilot remains justified. Preserve the newer behavior rather than restoring the old baseline:

- `workflow.ts` now owns eight native Mastra steps and serializable state; `attempt.ts` owns resources, memoized terminal persistence and cleanup. CLI and Studio share initialization after engine-run creation. The current ingestion guide's final claim that Studio registers no mutation workflows is stale; `src/mastra/index.ts`, the structure guide and current source-workflow spec establish executable Studio behavior.
- `agent.ts` uses native generation timeout/iteration limits, an external cancellation signal and retry allowance. Page/model-call counts are accounting, with no page cap or independent ordinary-call cap. Preparation no longer rejects source summaries against the old page budget.
- Logging and tracing share `runtime/observability/` ownership. Host log/trace fields are selected at call sites; the old trace-projection module is gone. The remaining `ResearchCatalog` type consumer is `runtime/tracing/labels.ts`.
- `classifyModelError` now uses `isMastraTimeoutError` from `@mastra/core/loop`. Keep that exact predicate as an explicit dependency of `model-errors.ts`; replacing it with a custom test or adapter would add behavior risk and indirection.

### Current reading path: execution and effects

The arrows below describe execution, not imports. Source links name current symbols; line anchors refer to the reviewed revision.

1. [catalog-options.ts: parseCatalogOptions](../../../../commands/catalog-options.ts#L15) accepts exactly one Event for refresh and defaults to `dryRun: !apply`. [catalog.ts: executeCatalogCommand](../../../../commands/catalog.ts#L104) performs database/report-path/target preflight, opens one connection, invokes each target, formats or exports the v2 report, returns an exit code, and closes the connection in `finally`.
2. [workflow.ts: runCatalogResearch](../../../../src/ingestion/workflow.ts#L555) creates the CLI engine run and starts the same [createCatalogIngestionWorkflow](../../../../src/ingestion/workflow.ts#L211) registered by [Studio ingestion](../../../../src/mastra/ingestion.ts). `onStart` resolves dependencies and constructs [CatalogAttempt](../../../../src/ingestion/attempt.ts#L31), which validates invocation/configuration, creates the budget, persists the start row and initializes optional observability. Failure before engine-run creation allocates no attempt. CLI retains its connection; Studio lazily acquires and releases its own connection while lending the shared observability store.
3. The graph is `initialize-run → load-context → read-initial-source → research-festival → prepare-candidate → apply-catalog-item → build-report → finalize-run`. Native state holds serializable accumulated data and each step returns its own result; attempt holds live resources, not a second data checkpoint. [context.ts: loadResearchContext](../../../../src/ingestion/research/context.ts#L11) calls the private [readResearchEvent](../../../../src/catalog/read/research.ts#L15), reads taxonomy terms and owner-qualified links, and gives refresh only the requested Event. [sources/session.ts: createSourceSession](../../../../src/ingestion/sources/session.ts#L23) owns cached read/search history and shared accounting; `readInitialWithTrace` precedes model execution. Pages are counted without a count cap.
4. [agent/index.ts: researchFestival](../../../../src/ingestion/research/agent/index.ts#L52) registers read/search tools and constructs the real agent or uses `generateCandidate`. `promptFor` builds JSON with saved context and bounded initial reads. Real execution uses `modelOutputSchema`, step usage/logging callbacks, provider retry processing, native generation timeout, iteration allowance and the workflow cancellation signal. The last ordinary step disables tools to request a final answer. `agentRuntime` reuses the observability-owned Mastra instance or owns a local instance. Generation completion time is recorded before local cleanup.
5. The agent retains the raw final response and returns a normalized candidate, still typed `unknown`. [prepare.ts: prepareResearch](../../../../src/ingestion/research/prepare.ts#L397) strictly parses it, records structural/target validation issues, checks the requested target, and builds ordered operations plus explanation mappings. It has no source-summary page cap. `prepareEdition` maps grouped fields, terms, tickets, links, then proposed publication. No model semantic verifier runs.
6. [apply-operation.ts: applyCatalogItem](../../../../src/catalog/write/apply-operation.ts#L842) resolves temporary IDs and threads versions through dependent operations. One outer item transaction encloses operation validation, writes, receipts, and audit. Dry-run encloses that same work in rollback while returning the preview. [applyCatalogOperation](../../../../src/catalog/write/apply-operation.ts#L797) validates each operation and checks its receipt hash; the writer remains authoritative for stored constraints and publication.
7. [report.ts: assembleReport](../../../../src/ingestion/report.ts#L55) joins actual writer changes to explanations by operation key and field name, derives outcome separately from research status, and combines research/discovery accounting. `finalize-run` calls `CatalogAttempt.finalize` outside catalog transactions, then returns a bounded Studio summary. CLI awaits the same memoized finalization promise for the complete v2 report. Terminal hooks recover bypassed finalization; cleanup waits for active work and releases only owned resources. [runs.ts](../../../../src/ingestion/runs.ts) owns guarded durable writes.

Meaningful branches must remain visible:

| Branch | Current behavior and owner |
| --- | --- |
| Zero agent allowance; native iteration exhaustion; generation failure/timeout | Agent returns research-stage failure; iteration exhaustion remains execution policy, while `classifyModelError` recognizes native timeout and retained host limits before safe diagnostics. Completed token counts survive; full cost becomes unknown when incomplete. |
| Explicit provider unavailable | `runtime/openrouter.ts: providerUnavailableRetry` owns eligibility/backoff. Agent callback adjusts step accounting; retry iterations preserve ordinary `agentSteps` capacity and waits remain within the deadline. Keep these calls/callbacks together. |
| Structured failed result | Agent may return `ok: true` because generation completed; `prepareResearch` accepts the failed envelope with no operations. Execution success is not research success. |
| Invalid structure / target | Preparation rejects before writing and records separate structural/target validation states. Unknown/required nulls survive normalization so strict rejection remains possible. |
| Partial valid result / duplicate add | Partial may write and remain partial; duplicate add returns skipped without operations. Shared execution makes both regression cases relevant to refresh refactoring. |
| Writer rejection | Item rollback; workflow adds `write_failed`, retaining research status, raw response, and summaries. |
| Unexpected workflow/report failure | Fallback report keeps known results, including a prior commit; `workflow_failed` makes the command fail. |
| Start/final persistence failure | Start failure prevents research; finalization failure does not undo a commit or replay research. All finalization callers receive the same memoized report or original persistence error; Studio exposes a bounded safe failure summary. |
| Cancellation / terminal cleanup | Workflow passes its abort signal into agent/tools, waits for active work, and finalizes known accounting before resources close. Cancellation prevents later writes but preserves confirmed commits. Generation completion time prevents cleanup from becoming a timeout. Injected generators and dry runs bypass tracing; independently enabled logging may still use the shared store. |
| Studio state / entry guards | Context, reads, research, prepared operations, receipts and reports are inspectable in local native state; prompts, credentials, transport envelopes and live resources remain excluded. Duplicate active IDs and unsupported replay/per-step starts cannot allocate or release another attempt. Snapshots and workflow retries remain disabled. |

These representations protect different boundaries. Repeated use of `majorToMinor` for candidate validation and conversion is shared enforcement, not competing precision policies. A single shared price type would erase meaningful distinctions.

## Goals / Non-Goals

**Goals:** A reader can locate research execution, explain important failures, follow the price round trip, and find an authoritative owner for each representation without reading provider lifecycle code for pure transformations. Preserve the exact external behavior, including failure precedence and model-visible bytes for fixed inputs.

**Non-Goals:** No framework migration, new provider interface, workflow/state-machine rewrite, report redesign, prompt improvement, semantic verification, schema/data migration, new live eval, repository-wide reorganization, or publication-rule consolidation. No new limits on lines, exports or navigation hops. This planning pass edits no application code, tests, prompt or check configuration.

## Decisions

### 1. Extract only three cohesive transformation owners

All paths are under `src/ingestion/research`; the responsibility table uses the final user-requested layout. The original findings above describe the reviewed baseline.

| Owner | Interface and responsibility | Benefit / indirection cost |
| --- | --- | --- |
| `agent/index.ts` (retain) | `researchFestival(...): Promise<ResearchExecution>`; keep `ModelUsage` and `ResearchExecution`, tool registration, Agent construction, step accounting/logging, `updateModelUsage`, `completedStepUsage`, `logModelFailure`, `isStructuredModelText`, native limits, cancellation, raw response retention, error-to-result mapping, `throwIfProviderRetry`, `isIterationExhausted`, `assertPromptSize`, and `agentRuntime`. | One execution entry with visible resource lifetime. Keeping usage next to callbacks avoids a stateful collector abstraction and hidden ordering. |
| `agent/input.ts` (new) | Move `promptFor` with the same arguments/return string, `modelContext(ResearchCatalog[number])`, `boundedToolSource(ReadSourceResult, maxChars?)`; keep `safeSource` private. Own prompt JSON using the static instructions in `agent/prompt.ts`, saved-price projection and model-visible source bounding. | Reader finds all model-facing input transformations together; both initial prompt and read tool use identical existing bounding. One module call replaces unrelated inline details. Prompt text moves verbatim, no edits or version bump. |
| `agent/prompt.ts` (new) | Export only the fixed `researchInstructions` string, preserving text verbatim. | Model wording can be edited without navigating JSON projection or execution code; no loader or template abstraction. |
| `agent/wire.ts` (new) | `modelOutputSchema()` derives JSON Schema from `researchCandidateSchema`; `normalizeWireCandidate(unknown, path?)` preserves its existing signature/recursion. Keep optional-null paths and schema cleaner private. | Places both directions of transport adaptation together without duplicating strict contracts. One extra import; no handwritten parallel wire DTO or automatic optional-path derivation. |
| `agent/errors.ts` (new) | `classifyModelError(error, deadline, finishedAt?)` returns the same limit/diagnostic shape. It does not catch, retry, log, or choose workflow outcomes. |
| `context.ts` (retain) | Keep `loadResearchContext`, `ResearchContext`; add `ResearchCatalog = ReturnType<typeof readResearchCatalog>`. | Data alias lives beside context construction. Type-only imports do not load its database implementation. No additional interface layer. |
| `contracts.ts`, `money.ts`, `prepare.ts` (retain) | Strict candidate/error/question contracts; shared currency precision conversion; candidate → `PreparedResearch` including operations, target gates, preflight publication and explanation mapping. | Existing useful boundaries survive. No per-field adapters or generic operation-builder framework. |

No production consumer currently imports the four helper exports from `agent.ts`; the direct consumers found are in `agent.test.ts`. Move those imports/tests to the relevant owners in the same stage. Keep the production `researchFestival`, `ModelUsage`, and `ResearchExecution` exports compatible; no compatibility barrel for internal helper locations. Update trace labels' `ResearchCatalog` type import as the sole necessary production seam outside research; its `PreparedResearch` import stays in prepare. No runtime changes to workflow, attempt, report, sources, logging/observability/tracing, OpenRouter, CLI, Studio or writer are planned. Keep agent-local `modelContext()` (step/attempt logging fields) in agent; it is unrelated to the exported saved-catalog `modelContext(target)` being moved.

Alternative: only add headings/comments to `agent.ts`. This is lower risk but leaves transformation ownership and tests tied to SDK execution, so it does not address F1/F2 sufficiently. Alternative: extract tools, execution runtime, usage collector and every preparation helper as well. Rejected: source session and runtime already own effects; further layers would hide timing/accounting coupling and require more navigation without an established benefit.

### 2. Proposed reading paths and permitted dependencies

Overview remains `CLI runCatalogResearch / Studio → createCatalogIngestionWorkflow → onStart CatalogAttempt → eight native steps → CatalogAttempt.finalize / cleanup`. Within the phase steps the path remains `loadResearchContext / source session → researchFestival → prepareResearch → applyCatalogItem → buildResearchReport`. A reader should not need to open the new modules merely to understand this execution order.

For a value, the new path is `private read → context → agent/input.modelContext / promptFor → model → wire.normalizeWireCandidate → contracts (strict parse in prepareResearch) → prepareTickets / money → writer → report`. For a failure it is `researchFestival catch → agent/errors.classifyModelError → research failure result → workflow/report`; retry and cleanup remain at the call site. More named files are acceptable only if the owner is easier to select.

Imports are a different view:

| Module | Allowed runtime dependencies within the application | Allowed type-only seams |
| --- | --- | --- |
| `agent/input.ts` | `money.ts` and static `agent/prompt.ts` | Context/catalog snapshot, ingestion input, source contracts, budget remaining shape. No runtime import of context, agent, prepare, workflow or storage. |
| `agent/prompt.ts` | None | None; this is only static instruction text. |
| `agent/wire.ts` | `contracts.ts` and Zod | Schema-derived types if needed; no agent, preparation, report, source execution, storage or framework dependency. |
| `agent/errors.ts` | `runtime/budget.ts` for `ResearchLimitError`, plus the existing `isMastraTimeoutError` predicate from `@mastra/core/loop` | Research error contract if needed; no agent instance, sources, storage, logging/tracing or provider client. The framework predicate is the sole explicit framework seam. |
| `contracts.ts` / `money.ts` | Existing Zod and pure catalog rules / currency validation; contracts → money | No reverse dependency from money to contracts or new model modules. |
| `context.ts` | Existing private catalog reads, database/taxonomy selection | Ingestion input and source link contracts. No writer, agent or preparation dependency. |
| `prepare.ts` | Existing contracts, money, URL normalization, Node crypto | Context snapshot, input and catalog operation types; no agent or new model modules. |
| `agent/index.ts` | The three new owners plus its existing framework/runtime/source-schema and logging/tracing dependencies | Existing context, source session, configuration, observability and injection contracts. It does not import writer or report. |

No new upward runtime edges from these modules to workflow, CLI or public web are permitted. Retain existing runtime → research **type-only** trace seams; do not mislabel them as runtime cycles. Imports must resolve identically through relative paths and `@/` aliases when audited. This is a review acceptance boundary now, not a new linter configuration.

### 3. Preserve contracts before moving code

The strict candidate schema, generated wire schema, prompt body and schema descriptions all influence behavior. Use deterministic input fixtures with a fixed `todayUtc`, fixed remaining budget and fixture source content. At the user's request after extraction, full prompt and response-schema snapshots were removed to reduce maintenance. Retain explicit assertions for saved-price/source projections, the reduced remaining-budget shape, provider schema compatibility and optional-null versus clearing semantics. These checks do not assert exact equality of the entire prompt or generated schema.

Keep `unknown` at the untrusted result boundary and retain separate raw and normalized objects. Do not collapse execution `ok`, candidate `status`, validation status, write state, outcome, or lifecycle. Preserve the current location/order of `generationFinishedAt`, native timeout/iteration options, cancellation checks, local runtime shutdown and attempt finalization. Preserve selected log fields and event timing, including structured-output exclusion from commentary; these side effects remain at their current call sites. Native workflow state and step outputs must retain the same research/modelResponse/preparation representations. No live evaluation is needed to demonstrate a mechanical extraction; deterministic equality cannot promise identical future model answers.

## Risks / Trade-offs

- **Serialization drift during a move** → Characterize fixed input strings, tool projection output and response schema first; preserve key order, omitted fields, truncation boundaries, descriptions and prompt version. Reject incidental wording cleanup.
- **More navigation** → Limit extraction to the three responsibilities in the table. Compare the same reader probes; if readers still need execution internals to understand pure conversion, revise boundaries before completion.
- **Null policy remains manually synchronized with contracts** → Keep it explicit and adjacent, with positive/negative fixtures for wrapper null, inner null, required null and unknown fields. Extraction does not eliminate this deliberate compatibility policy.
- **Helper tests bypass real orchestration** → Retain existing offline real-Mastra provider, tracing and Studio transport integration tests as contract witnesses; pure tests alone are insufficient.
- **Type alias movement accidentally loads storage** → Require `import type`, run type-check/lint and inspect emitted/runtime import relationships; do not move context loading or create a new read model.
- **Temptation to fix publication overlap** → Retain current preflight and writer checks; record F4 for separate consideration. No demonstrated mismatch was established in this review.
- **Ambiguous old cost wording** → The source-workflow scenario “A provider failure follows completed work” says retain known cost, while its later accounting scenarios explicitly keep full `modelCostUsd` null when incomplete. Preserve observed code/tests: known tokens survive, full cost becomes null. Do not use this refactor to reinterpret or rewrite the spec.

## Migration Plan

Implementation starts only on a subsequent apply request. Every stage is independently type-checkable/testable and can be reverted as a source change; there is no data migration, release choreography, or database rollback script.

1. Establish the behavior baseline with the existing offline suite and only missing characterization for prompt/schema, input projections and diagnostic behavior. New expectations must pass against the original implementation before production moves.
2. Extract the three owners sequentially, moving their tests with them. Combine the context alias relocation with model-input extraction, then extract wire adaptation and error classification. Verify each step with focused tests and type-checking; update the existing structure paragraph once within this stage after the extractions pass.
3. Run the complete relevant suite and standard static checks, then review clarity and scope against the current reading path in this design. Record results and remaining friction in task completion notes; no separate baseline reader protocol or planning document is required.
