# Promo copy template

Write as the Eventroam team. Replace the text in brackets with details from the project.

## Homepage

### Headline and introduction

We turn [source material] into [data a reader can use]. We can deliver [records] to your product or build the pipeline your team needs to [task].

### Process example

Choose a published festival edition with a saved change. Link to the sources that the team compared. Show what each source says, how the team matched the edition, and which field changed. Check the old and new values in the catalog history. Link to the published result.

### Services

For the data product, name a decision the data supports. For custom development, name an input the team works with and the output it needs. Link each service to its page.

### Live example

See how [product] uses the data to [task]. Link to the result.

### Work with us

Tell us what you want to do with your data.

[Discuss your project](mailto:hello@eventroam.org)

## Data product

### Use case

A [type of user] needs to [make a decision]. Our data includes [specific fields]. Your product can use them to [show a concrete result].

Use market research to find buyer tasks. Present them as possible uses unless you have evidence of a customer deployment.

For an API example, check the response used by the product. Use the list response for discovery fields and the edition response for ticket details. Keep conditions from the ticket terms. Say when fields such as map coordinates can be missing.

### Example record

Use a published record. Show which item it describes, which facts belong to it, and how a product uses several of those facts together. Link to the record in the catalog.

### Work with us

Tell us which region or sources you need, which fields your product uses, and how often you need updates.

[Discuss your data needs](mailto:hello@eventroam.org)

## Custom data pipelines

### Introduction

We build pipelines that read [client sources], check [facts or changes], and send [output] to [destination].

### Pipeline example

Use one example throughout the diagram. Show the input, what each agent reads or extracts, the checks before delivery, and what happens when the source is unclear. Identify who reviews an exception and where an approved record goes.

### Possible solutions

Name [a task], [an input], and [the result] for each solution. Use this page for examples from other sectors. Introduce proposed systems with “We can build”.

### A system in use

Describe one change in a live project. Show the result a reader can check. For example, link to both festival editions when a case compares venues across years.

### Work with us

Send us a sample input and an example of the output your team needs.

[Discuss your pipeline](mailto:hello@eventroam.org)

## Before publishing

- Check each case against its source and the published record. Name the source in the text when the page omits a source link.
- Give the edition or date for a fact that can change. Identify prices from an announcement and keep terms that affect the comparison.
- Label illustrative data as an example. Use claims about savings, accuracy, or customer outcomes only when you have evidence for them.
