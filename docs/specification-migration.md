# Specification migration map

This map records where the eight former `specs/` documents went. The five files under [legacy specs](archive/legacy-specs/), together with the [vocabulary proposal](proposals/festival-taxonomy-vocabulary.md), preserve the complete original wording for historical comparison. They are not current behavior contracts. Main [OpenSpec specs](../openspec/specs/) cover implemented behavior; [active changes](../openspec/changes/) cover approved future work; [draft proposals](proposals/) hold choices that are not approved. The current implementation was checked against [build progress](service-build-progress.md) and code during migration.

OpenSpec's [standard spec-driven schema](https://github.com/Fission-AI/OpenSpec/blob/main/docs/opsx.md) is used; user goals live in change proposals and acceptance behavior lives in requirement scenarios. Future changes deliberately have no design or tasks yet where implementation interfaces remain undecided.
